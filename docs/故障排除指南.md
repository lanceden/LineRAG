## 🎯 故障排除概述

本指南提供 LineRAG 系統常見問題的診斷方法和解決方案，按照問題類型分類，包含詳細的排除步驟和預防措施。

### 故障分級
- **P0 - 緊急**: 系統完全無法使用
- **P1 - 高優先級**: 核心功能受影響
- **P2 - 中優先級**: 部分功能異常
- **P3 - 低優先級**: 輕微問題或改進建議

## 🚨 緊急故障處理 (P0)

### 系統完全無法存取

#### 症狀
- 網站無法開啟
- API 完全無回應
- 所有服務停止

#### 診斷步驟
```bash
# 1. 檢查伺服器狀態
ping your-domain.com

# 2. 檢查系統負載
uptime
top

# 3. 檢查磁碟空間
df -h

# 4. 檢查記憶體使用
free -h

# 5. 檢查關鍵服務
systemctl status nginx
systemctl status linerag-api
systemctl status postgresql
systemctl status qdrant
```

#### 解決方案
```bash
# 緊急重啟程序
#!/bin/bash
echo "執行緊急恢復程序..."

# 檢查並清理磁碟空間
if [ $(df / | tail -1 | awk '{print $5}' | sed 's/%//') -gt 90 ]; then
    echo "清理磁碟空間..."
    find /var/log -name "*.log" -mtime +7 -delete
    find /tmp -type f -mtime +1 -delete
    docker system prune -f
fi

# 重啟核心服務
systemctl restart postgresql
sleep 10
systemctl restart qdrant
systemctl restart redis
sleep 5
systemctl restart linerag-api
sleep 5
systemctl restart nginx

# 驗證服務狀態
curl -f http://localhost:8000/api/health || echo "API 服務異常"
curl -f http://localhost:3000 || echo "Web 服務異常"
```

### 資料庫完全無法連接

#### 症狀
- API 回傳資料庫連接錯誤
- PostgreSQL 服務無法啟動
- 連接超時

#### 診斷步驟
```bash
# 檢查 PostgreSQL 服務狀態
systemctl status postgresql

# 檢查 PostgreSQL 日誌
tail -50 /var/log/postgresql/postgresql-15-main.log

# 檢查連接配置
sudo -u postgres psql -c "SHOW max_connections;"
sudo -u postgres psql -c "SELECT count(*) FROM pg_stat_activity;"

# 檢查磁碟空間 (PostgreSQL 資料目錄)
df -h /var/lib/postgresql/
```

#### 解決方案
```bash
# 1. 重啟 PostgreSQL
systemctl restart postgresql

# 2. 如果無法啟動，檢查配置
sudo -u postgres pg_ctl status -D /var/lib/postgresql/15/main

# 3. 修復權限問題
chown -R postgres:postgres /var/lib/postgresql/15/main
chmod 700 /var/lib/postgresql/15/main

# 4. 清理連接
sudo -u postgres psql -c "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE state = 'idle' AND state_change < now() - interval '1 hour';"

# 5. 如果資料損壞，從備份恢復
# (參考備份恢復程序)
```

## ⚠️ 高優先級問題 (P1)

### API 回應緩慢

#### 症狀
- API 回應時間 > 5 秒
- 用戶反映系統卡頓
- 超時錯誤增加

#### 診斷步驟
```bash
# 1. 檢查 API 回應時間
curl -w "@curl-format.txt" -o /dev/null -s http://localhost:8000/api/health

# 2. 檢查系統資源
htop
iostat -x 1 5

# 3. 檢查資料庫效能
sudo -u postgres psql linerag_db -c "
SELECT query, mean_exec_time, calls 
FROM pg_stat_statements 
ORDER BY mean_exec_time DESC 
LIMIT 10;"

# 4. 檢查慢查詢
sudo -u postgres psql linerag_db -c "
SELECT pid, now() - pg_stat_activity.query_start AS duration, query 
FROM pg_stat_activity 
WHERE (now() - pg_stat_activity.query_start) > interval '5 minutes';"
```

#### 解決方案
```bash
# 1. 重啟 API 服務
systemctl restart linerag-api

# 2. 清理資料庫連接
sudo -u postgres psql -c "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE state = 'idle in transaction' AND state_change < now() - interval '10 minutes';"

# 3. 更新資料庫統計
sudo -u postgres psql linerag_db -c "ANALYZE;"

# 4. 清理快取
redis-cli FLUSHALL

# 5. 重建索引 (如果需要)
sudo -u postgres psql linerag_db -c "REINDEX DATABASE linerag_db;"
```

### LINE Webhook 無法接收訊息

#### 症狀
- LINE 用戶發送訊息無回應
- Webhook 端點回傳錯誤
- LINE 平台顯示 Webhook 失敗

#### 診斷步驟
```bash
# 1. 檢查 Webhook 端點
curl -X POST http://localhost:8000/api/webhook \
  -H "Content-Type: application/json" \
  -d '{"events": []}'

# 2. 檢查 LINE Channel 設定
grep "LINE_CHANNEL" /opt/linerag/apps/api/.env

# 3. 檢查 Nginx 日誌
tail -50 /var/log/nginx/access.log | grep webhook

# 4. 檢查 API 日誌
tail -50 /var/log/linerag/api.log | grep webhook
```

#### 解決方案
```bash
# 1. 驗證 LINE Channel 設定
# 確認 .env 檔案中的 LINE_CHANNEL_ACCESS_TOKEN 和 LINE_CHANNEL_SECRET

# 2. 測試 LINE API 連接
curl -X POST https://api.line.me/v2/bot/message/push \
  -H "Authorization: Bearer YOUR_CHANNEL_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "to": "USER_ID",
    "messages": [{"type": "text", "text": "測試訊息"}]
  }'

# 3. 重新設定 Webhook URL
# 在 LINE Developers Console 中重新設定 Webhook URL

# 4. 重啟相關服務
systemctl restart linerag-api
systemctl restart nginx
```

### 檔案上傳失敗

#### 症狀
- 檔案上傳回傳錯誤
- 上傳進度卡住
- 檔案處理失敗

#### 診斷步驟
```bash
# 1. 檢查上傳目錄權限
ls -la /opt/linerag/uploads/

# 2. 檢查磁碟空間
df -h /opt/linerag/

# 3. 檢查檔案大小限制
grep "client_max_body_size" /etc/nginx/nginx.conf
grep "MAX_FILE_SIZE" /opt/linerag/apps/api/.env

# 4. 檢查處理日誌
tail -50 /var/log/linerag/api.log | grep upload
```

#### 解決方案
```bash
# 1. 修復目錄權限
chown -R linerag:linerag /opt/linerag/uploads/
chmod 755 /opt/linerag/uploads/

# 2. 清理臨時檔案
find /opt/linerag/uploads/temp -type f -mtime +1 -delete

# 3. 增加檔案大小限制 (如果需要)
# 編輯 /etc/nginx/nginx.conf
# client_max_body_size 100M;

# 4. 重啟服務
systemctl restart nginx
systemctl restart linerag-api
```

### 用戶認證問題

#### 症狀
- 登入失敗
- Token 過期錯誤
- 權限拒絕

#### 診斷步驟
```bash
# 1. 檢查 JWT 設定
grep "JWT_SECRET_KEY" /opt/linerag/apps/api/.env

# 2. 測試登入 API
curl -X POST http://localhost:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "admin@linerag.com", "password": "password"}'

# 3. 檢查用戶資料
sudo -u postgres psql linerag_db -c "SELECT id, email, is_active FROM system_users;"

# 4. 檢查認證日誌
grep "auth" /var/log/linerag/api.log | tail -20
```

#### 解決方案
```bash
# 1. 重設用戶密碼
sudo -u postgres psql linerag_db -c "
UPDATE system_users 
SET password_hash = '$2b$12$...' 
WHERE email = 'admin@linerag.com';"

# 2. 清理過期 Token (如果使用 Redis)
redis-cli FLUSHDB

# 3. 重新生成 JWT Secret
# 更新 .env 檔案中的 JWT_SECRET_KEY

# 4. 重啟 API 服務
systemctl restart linerag-api
```

## 🔍 低優先級問題 (P3)

### 日誌檔案過大

#### 症狀
- 磁碟空間不足警告
- 日誌檔案佔用大量空間
- 系統效能下降

#### 解決方案
```bash
# 1. 手動清理舊日誌
find /var/log -name "*.log" -mtime +30 -delete
find /var/log -name "*.log.*" -mtime +7 -delete

# 2. 配置日誌輪轉
cat > /etc/logrotate.d/linerag << EOF
/var/log/linerag/*.log {
    daily
    missingok
    rotate 30
    compress
    delaycompress
    notifempty
    create 644 linerag linerag
    postrotate
        systemctl reload linerag-api
    endscript
}
EOF

# 3. 立即執行日誌輪轉
logrotate -f /etc/logrotate.d/linerag

# 4. 調整日誌等級
# 編輯 .env 檔案，將 LOG_LEVEL 從 DEBUG 改為 INFO
```

## 🛠️ 診斷工具和腳本

### 系統健康檢查腳本

```bash
#!/bin/bash
# health_check.sh - 全面系統健康檢查

echo "=== LineRAG 系統健康檢查 ==="
echo "檢查時間: $(date)"
echo

# 檢查服務狀態
echo "1. 服務狀態檢查"
services=("nginx" "linerag-api" "postgresql" "qdrant" "redis")
for service in "${services[@]}"; do
    if systemctl is-active --quiet $service; then
        echo "✅ $service: 運行中"
    else
        echo "❌ $service: 停止"
    fi
done
echo

# 檢查系統資源
echo "2. 系統資源檢查"
cpu_usage=$(top -bn1 | grep "Cpu(s)" | awk '{print $2}' | awk -F'%' '{print $1}')
mem_usage=$(free | grep Mem | awk '{printf("%.1f", $3/$2 * 100.0)}')
disk_usage=$(df -h / | awk 'NR==2{print $5}' | sed 's/%//')

echo "CPU 使用率: ${cpu_usage}%"
echo "記憶體使用率: ${mem_usage}%"
echo "磁碟使用率: ${disk_usage}%"

if [ $(echo "$cpu_usage > 80" | bc) -eq 1 ]; then
    echo "⚠️  CPU 使用率過高"
fi
if [ $(echo "$mem_usage > 80" | bc) -eq 1 ]; then
    echo "⚠️  記憶體使用率過高"
fi
if [ $disk_usage -gt 80 ]; then
    echo "⚠️  磁碟使用率過高"
fi
echo

# 檢查 API 健康狀態
echo "3. API 健康狀態檢查"
api_response=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:8000/api/health)
if [ "$api_response" = "200" ]; then
    echo "✅ API 服務正常"
else
    echo "❌ API 服務異常 (HTTP $api_response)"
fi

# 檢查資料庫連接
echo "4. 資料庫連接檢查"
if sudo -u postgres psql -c "SELECT 1;" > /dev/null 2>&1; then
    echo "✅ PostgreSQL 連接正常"
    
    # 檢查連接數
    conn_count=$(sudo -u postgres psql -t -c "SELECT count(*) FROM pg_stat_activity;")
    echo "當前連接數: $conn_count"
    
    if [ $conn_count -gt 150 ]; then
        echo "⚠️  資料庫連接數過高"
    fi
else
    echo "❌ PostgreSQL 連接失敗"
fi

# 檢查 Qdrant 服務
echo "5. Qdrant 服務檢查"
qdrant_response=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:6333/health)
if [ "$qdrant_response" = "200" ]; then
    echo "✅ Qdrant 服務正常"
else
    echo "❌ Qdrant 服務異常 (HTTP $qdrant_response)"
fi

echo
echo "=== 健康檢查完成 ==="
```

### 效能診斷腳本

```bash
#!/bin/bash
# performance_diagnosis.sh - 效能問題診斷

echo "=== LineRAG 效能診斷 ==="

# API 回應時間測試
echo "1. API 回應時間測試"
for i in {1..5}; do
    response_time=$(curl -w "%{time_total}" -o /dev/null -s http://localhost:8000/api/health)
    echo "測試 $i: ${response_time}s"
done

# 資料庫效能檢查
echo "2. 資料庫效能檢查"
sudo -u postgres psql linerag_db -c "
SELECT 
    schemaname,
    tablename,
    seq_scan,
    seq_tup_read,
    idx_scan,
    idx_tup_fetch
FROM pg_stat_user_tables
ORDER BY seq_scan DESC
LIMIT 10;"

# 慢查詢檢查
echo "3. 慢查詢檢查"
sudo -u postgres psql linerag_db -c "
SELECT 
    query,
    mean_exec_time,
    calls,
    total_exec_time
FROM pg_stat_statements 
ORDER BY mean_exec_time DESC 
LIMIT 5;"

# 系統負載檢查
echo "4. 系統負載檢查"
uptime
iostat -x 1 3

echo "=== 效能診斷完成 ==="
```
